初识Spring Cloud

微服务架构

微服务架构：
“微服务”一词源于 Martin Fowler的名为 Microservices的博文,可以在他的官方博客上找到
[博客地址][http://martinfowler.com/articles/microservices.html]

  • 微服务是系统架构上的一种设计风格,它的主旨是将一个原本独立的系统拆分成多个小型服务,这些小型服务都在各自独立的进程中运行,服务之间一般通过 HTTP 的 RESTfuLAPI 进行通信协作。
  • 被拆分成的每一个小型服务都围绕着系统中的某一项或些耦合度较高的业务功能进行构建,并且每个服务都维护着自身的数据存储、业务开发自动化测试案例以及独立部署机制。
  • 由于有了轻量级的通信协作基础,所以这些微服务可以使用
    不同的语言来编写。

概述

  • Spring Cloud 是一系列框架的有序集合。
  • Spring Cloud 并没有重复制造轮子，它只是将目前各家公司开发的比较成熟、经得起实际考验的服务框架组合起来。
  • 通过 Spring Boot 风格进行再封装屏蔽掉了复杂的配置和实现原理，最终给开发者留出了一套简单易懂、易部署和易维护的分布式系统开发工具包。
  • 它利用Spring Boot的开发便利性巧妙地简化了分布式系统基础设施的开发，如服务发现注册、配置中心、消息总线、负载均衡、 断路器、数据监控等，都可以用Spring Boot的开发风格做到一键启动和部署。
  • [Spring Cloud项目官方网址][https://spring.io/projects/spring-cloud]
  • Spring Cloud 版本命名方式采用了伦敦地铁站的名称，同时根据字母表的顺序来对应版本时间顺序，比如：最早的Release版本：Angel，第二个Release版本：Brixton，然后是Camden、Dalston、Edgware，Finchley，Greenwich，Hoxton。

Spring Cloud 和dubbo对比

Spring Cloud 和dubbo对比

  • Spring Cloud 与 Dubbo 都是实现微服务有效的工具。
  • Dubbo 只是实现了服务治理，而 Spring Cloud 子项目分别覆盖了微服务架构下的众多部件。
  • Dubbo 使用 RPC 通讯协议，Spring Cloud 使用 RESTful 完成通信，Dubbo 效率略高于 Spring Cloud。

总结

  • 微服务就是将项目的各个模块拆分为可独立运行、部署、测试的架构设计风格。

  • Spring 公司将其他公司中微服务架构常用的组件整合起来，并使用 SpringBoot 简化其开发、配置。

    称为 Spring Cloud

  • Spring Cloud 与 Dubbo都是实现微服务有效的工具。Dubbo 性能更好，而 Spring Cloud 功能更全面。

hystrix熔断器

概念

  • Hystix 是 Netflix 开源的一个延迟和容错库，用于隔离访问远程服务、第三方库，防止出现级联失败（雪崩）
    雪崩：一个服务失败，导致整条链路的服务都失败的情形

主要功能

  • 隔离

    • 线程池隔离
    • 信号量隔离

  • 降级

    • 提供方降级

      • 引入Hystrix依赖

      • 引导类添加@EnableCircuitBreaker注解

      • 编写降级方法

      • 使用@HystrixCommand配置降级方法

      • 降级场景

        • 出现异常
        • 请求超时

    • 消费方降级

      • feign集成了hystrix

      • 编写feign接口实现类，重写的方法为降级方法

        • 注：添加类到spring容器@Component

      • 在接口@FeignClient上添加fallback属性为实现类字节码

      • 配置文件中开启feign对hystrix的支持

  • 熔断

    • 概念

      • 监控微服务的调用情况，如果失败的次数过多，开启断路器，拒绝所有请求，都走降级方案，直到服务器恢复

      • 执行流程

        • 断路器一开始处于关闭状态
        • 如果失败到达一定次数，开启断路器，拒绝请求，走降级
        • 断路器开启后，默认五秒，半开，放行一些请求，如果成功次数达到一定次数，关闭断路器
        • 如果依旧请求失败，断路器继续开启

      • 配置

        • circuitBreaker.sleepWindowInMilliseconds：监控时间
          circuitBreaker.requestVolumeThreshold：失败次数
          circuitBreaker.errorThresholdPercentage：失败率

    • 监控

      • Hystrix 提供了 Hystrix-dashboard 功能，用于实时监控微服务运行状态。
        但是Hystrix-dashboard只能监控一个微服务。
        Netflix 还提供了 Turbine ，进行聚合监控。

  • 限流

Gateway网关

概念

  • 网关旨在为微服务架构提供一种简单而有效的统一的API路由管理方式，在微服务架构中，不同的微服务可以有不同的网络地址，各个微服务之间通过互相调用完成用户请求，客户端可能通过调用N个微服务的接口完成一个用户请求

  • 存在的问题

    1. 客户端多次请求不同的微服务，增加客户端的复杂性
    2. 认证复杂，每个服务都要进行认证
    3. http请求不同服务次数增加，性能不高

  • 网关就是系统的入口，封装了应用程序的内部结构，为客户端提供统一服务，一些与业务本身功能无关的公共逻辑可以在这里实现，诸如认证、鉴权、监控、缓存、负载均衡、流量管控、路由转发等

  • 类似nginx的功能，但nginx无法在代理的同时编写代码

    目前的网关解决方案里，有Nginx+ Lua、Netflix Zuul 、Spring Cloud Gateway等等

快速入门

  • 引入starter-gateway依赖

  • 编写启动类

  • 编写配置文件

过滤器

  • 概念

    • 对请求或响应进行拦截，完成一些通用操作

  • 过滤方式

    • pre过滤器

      • 可以在网关转发请求之前执行

      • 应用场景

        • 参数，权限校验，流量监控，日志输出，协议转换等

    • post过滤器

      • 可以在响应之前执行

      • 应用场景

        • 响应内容或响应头的修改，日志，流量监控

  • 过滤类型

    • GatewayFilter:局部过滤器

      • 在要拦截的配置路由下添加拦截

    • GlobalFilter全局过滤器

      • 定义类实现 GlobalFilter 和 Ordered接口

      • 重写方法，完成操作后放行

      • 重写getOrder方法可根据返回值的大小选择自定义拦截器的执行顺序，返回越小越先执行

config

概念

  • 解决分布式情况下多种配置文件的管理和维护

好处

  • 集中管理配置文件
  • 不同的配置环境不同的配置，动态的配置更新
  • 配置信息改变时，不需要重启服务即可更新到服务

快速入门

  • 将配置文件上传到git仓库，并克隆到本地

  • 服务端

    • 导入服务端依赖

    • 配置文件，指定git仓库地址，分支等

    • 注册到eureka中

      引导类添加注解@EnableConfigServer，启用config server功能

  • 客户端

    • 导入依赖

    • 创建bootstrap.yml配置文件

      bootstrap.yml优先级大于application.yml,一般用于加载系统配置等

    • 集成Eureka指定config服务地址（从eureka中获取），分支，文件名，开发环境即可,工程中bootstrap.yaml中注掉写死的地址，改为从Eureka中获取

    • 如何刷新

      • 引入actuator依赖

      • 获取配置文件的类上添加刷新注解 @RefreshScope

      • 添加配置management.endpoints.web.exposure.include: refresh

      • cmd使用crul发送post请求刷新

从git中获取的配置优先级高于模块中的配置

注意：启动中的服务端口无法更改

bus

概念

  • Spring Cloud Bus 是用轻量的消息中间件将分布式的节点连接起来，可以用于广播配置文件的更改或者服务的监控管理。关键的思想就是，消息总线可以为微服务做监控，也可以实现应用程序之间相互通信。

    Spring Cloud Bus 可选的消息中间件包括 RabbitMQ 和 Kafka

快速入门

  • 导入bus依赖

  • config服务端和客户端都添加rabbitMQ或kafka连接属性，这里例子使用rabbitMQ

    bootstrap.yml

  • 在要有引用配置文件的类上添加@RefreshScope注解

  • 在config服务端暴露刷新的端点

  • 刷新config可以通过给bus发送刷新信息来通知所有的config更新

stream

概念

  • 构建消息驱动微服务框架,springcloud支持rabbitmq和kafka,类似jdbc概念
  • 可以无缝切换rabbitmq和kafka,不用修改代码

stream组件

  • binding 是我们通过配置把应用和spring cloud stream 的 binder 绑定在一起

  • output：发送消息 Channel，内置 Source接口

  • input：接收消息 Channel，内置 Sink接口

生产者

  • 导入依赖

  • 编写配置,定义binder和bindings

  • 定义消息发送业务类,添加@EnableBinding(Source.class),注入MessageChannel output,完成消息发送

    MessageProducer

    ProducerController

消费者

  • 导入依赖

  • 编写配置,定义binder和bindings

  • 定义消息接收业务类,添加@EnableBinding(Sink.class),使用@StreamListener(Sink.INPUT),完成接收

Sleuth+Zipkin

Sleuth

  • 概念

    • 分布式链路追踪工具，能跟踪一个用户请求的过程，捕获这些跟踪数据，就能构建微服务的整个调用链的视图，这是调试和监控微服务的关键工具
    • 用于调试和监控微服务
    • 耗时分析 可视化错误 链路优化

Zipkin

  • 概念
    • 致力于收集服务的定时数据，以解决微服务架构中的延迟问题，用于数据的收集、存储、查找和展现

快速入门

  • 安装zipkin,运行java -jar zipkin.jar，访问zipkin web界面 http://localhost:9411/

  • 服务提供消费方都导入依赖

  • provider

  • consumer

  • 测试访问 http://localhost:9411/
