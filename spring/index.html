spring

概念

是半成品软件,简化开发步骤,提高开发效率,增强可用性,提供编写规范,节约维护成本,解耦底层实现原理

主要:IoC控制反转,AOP编程

由工厂模式发展而来,通过修改配置文件即可完成修改业务需求

IoC控制反转

概念

  • 控制反转,spring控制所需要的外部资源,spring将资源都存放到一个容器中,可理解为存放到一个map集合中,id为键,value为值

配置

  • bean标签

    • id:为bean的名称,通过id值获取实体

    • class:bean名称,即全类名

    • name:起的别名,也可通过别名获取实体

    • scope:bean是否单例

      • singleton:单例,spring容器加载完成后(配置文件加载后)就创建对象
      • prototype:多例,在获取对象时才进行创建操作

    • init-method,destroy-method:在对象初始化或销毁时完成的方法

      • 如果对象scope为prototype,spring创建之后不进行维护,销毁操作不执行
      • init-method=”方法名”

    • factory-bean:通过静态工厂方式获取bean

      • FactoryClassName:工厂类的全类名

      • factoryMethodName:工程类静态获取对象方法名

    • factory-method:通过非静态工厂方式获取bean

      • factoryBeanId:工厂类对象 配置的bean标签id,即先创建一个bean标签创建一个对象给当前的factorybean用于获取对象

      • factoryMethodName:工程类获取对象方法名

DI依赖注入

概念

  • 理解为:获取对应对象时,spring自动对其内的对象进行赋值,获取之后的对象内可直接进行使用

set方式注入

  • bean内子标签property

    propertyName:属性名,即set方法后的变量名首字母小写
    propertyValue:属性值,普通数据类型及String类型
    beanId:属性值,引用数据类型,要引用的beanId

构造方法注入

  • bean内子标签constructor-arg

    name:对应bean中的构造方法携带到的参数名
    value:设定非引用类型构造方法参数对应的值,不能与ref同时使用
    其他属性:
    ref：设定引用类型构造方法参数对应bean的id ，不能与value同时使用
    ​type ：设定构造方法参数的类型，用于按类型匹配参数或进行类型校验
    index ：设定构造方法参数的位置，用于按位置匹配参数，参数index值从0开始计数

集合类型注入

  • array

    • 值

  • list

    • 值 值

  • props

    • 值 值

  • set

    • 值

  • map

p:propertyName,p:propertyName-ref

  • 使用p命令空间需要先开启spring对p命令空间的的支持，在beans标签中添加对应空间支持

SpEL

  • 使用value = “#{值}”,如果值为字符串,则需要加单引号包裹,用于同一使用value属性

导入properties文件

  • 准备外部properties文件
  • 开启context命名空间支持
  • 加载指定properties文件或*.properties
  • 使用加载数据${properties文件内键名}
  • 开启命名空间支持同时需添加标签约束

导入其他spring配置文件中的项

  • <import resource=“classpath:要导入文件名”/>
  • Spring容器中的bean定义冲突问题

同id的bean，后定义的覆盖先定义的
导入配置文件可以理解为将导入的配置文件复制粘贴到对应位置
导入配置文件的顺序与位置不同可能会导致最终程序运行结果不同

配置文件整合mybatis

  • 引入坐标
  • 在业务层提供变量和set方法,进行依赖注入
  • spring核心配置文件中配置bean注入,配置的ref为接口名首字母小写
  • 添加contex命名空间,引入jdbc配置文件
  • 创建dataSource对象,注入连接信息,从jdbc配置文件中获取连接信息
  • 创建SqlSessionFactoryBean对象,注入dataSource和起别名要扫描的包
  • 创建映射扫描对象,并注入要扫描的包

注解开发

创建bean注解

  • 添加bean到IoC容器:component,controller,service,repositor,repository value属性为id值,方便获取
  • 作用域:scope 在类上方定义
  • 生命周期:PostConstruct,PreDestroy 在方法上定义 对应init和destroy方法
  • 加载第三方资源:bean 在方法上定义,在方法内完成对象创建并完成手动注入,返回要添加到容器中的对象,当前方法所在类需要添加到IoC容器中

依赖注入注解

  • 非引用类型注入

    • Value:属性或set方法上定义,value只支持非引用数据类型,支持读取properties文件中属性值

  • 引用类型注入

    • Autowired:属性或set方法上定义,Autowired优先按照类型进行匹配对象,匹配成功自动注入,如果有多个相同类型的对象,优先按成员变量名和容器中匹配的bean名称进行注入
    • Qualifier:和Autowired定义相同,如果没有找到,则通过Quelifier(“beanId”)按照名称进行匹配
    • Primary:定义在类上方,设置类如果有多个相同对象,当前作用类优先注入
    • @Inject、@Named、@Resource 由JDK提供的注解 inject,Named对应Autowired,Qualifier
      Resource:name设置注入的beanId,type设置注入的类型

  • 导入properties文件注解

    • PropertySource:定义在类上 value属性写配置文件路径名(可传入数组,使用大括号包裹),如果资源找不到,可加上ignoreResourceNotFound属性,是否忽略,默认为false 文件路径不支持*通配符

  • 纯注解替换配置文件

    • Configuration:定义在类上
    • ComponentScan:定义在类上,value为要扫描的包
    • 加载配置文件改为加载配置的类,使用 AnnotationConfigApplicationContext创建一个对象传入要加载的配置类字节码文件
    • Import导入其他的配置类,如果需要导入多个配置类,使用大括号包裹,@bean所在类可以使用导入的方法进入IoC容器

bean加载控制

  • DependsOn:定义在类或方法上,用于控制bean的加载顺序,使其在指定bean加载完成后再加载
  • Order:配置类注解,控制加载顺序,传入int值,数值越小越先加载
  • Lazy:定义在类或方法上,控制bean的加载时机,使其延迟加载
  • 添加注解扫描:<context:component-scan base-package=”要扫描的包”/>

注解整合junit

  • 添加坐标
  • @RunWith(SpringJUnit4ClassRunner.class)
  • @ContextConfiguration(classes = 配置类的字节码文件) 如果是要加载配置文件则属性改为locations=”classpath:applicationContext.xml”

IoC底层核心原理

IoC核心接口

  • BeanFactory

组件扫描过滤器

  • ComponentScan

    • 扫描指定的类,并加入ioc容器

自定义导入器

  • 需要大量配置bean的方式

  • 实现ImportSelector,实现selectImports方法

    • 返回的字符串数组中添加要配置bean的全类名

  • 在配置类中使用import注解导入自定义的导入器

bean初始化过程

  • BeanFactoryPostProcessor

    • 作用：定义了在bean工厂对象创建后，bean对象创建前执行的动作，用于对工厂进行创建后业务处理
    • 运行时机：当前操作用于对工厂进行处理，仅运行一次

  • BeanPostProcessor

    • 作用：定义了所有bean初始化前后进行的统一动作，用于对bean进行创建前业务处理与创建后业务处理
    • 运行时机：当前操作伴随着每个bean的创建过程，每次创建bean均运行该操作

  • InitializingBean

    • 作用：定义了每个bean的初始化前进行的动作，属于非统一性动作，用于对bean进行创建前业务处理
    • 运行时机：当前操作伴随着任意一个bean的创建过程，保障其个性化业务处理

FactoryBean与BeanFactory区别

  • FactoryBean：封装单个bean的创建过程,对单一的bean的初始化过程进行封装，达到简化配置的目的
  • BeanFactory：Spring容器顶层接口，定义了bean相关的获取操作

AOP

概念

  • 面向切面编程,编程范式,对OOP进行弥补,对共性功能抽取,自定义功能代码不需更改,对自定义功能进行增强

  • 连接点表示目标对象内的方法

  • 切点代表要增强功能的方法

  • 通知代表要增强的功能代码

    • 通知类型:前置通知等…

  • 切面表示增强完成后的方法

配置文件配置AOP

  • 引入AspectJ

  • 目标对象和通知创建

  • 配置文件进行配置

    • aop:config 开启AOP配置

      • <aop:pointcut id,expression> 设置切入点
        id:在aspect内需要引用的id
        expression:execution表达式

      • <aop:aspect ref>设置要生效对应的切入点
        ref:spring容器中的通知类id

        • <aop:通知类型 method,pointcut-ref>
          method:通知类内要增强的方法名
          pointcut-ref:pointcut中设置的要增强的id

execution表达式:(权限修饰符 返回值类型 包名.类名.方法名(参数))

  • *表示所有,在参数内表示一个随意类型参数
  • ..表示多个连续的任意符号,简化包名或参数,在参数内表示任意个随意参数类型参数
  • *专用于匹配子类类型,子类或实现类

通知类型

  • before

    • 在要增强方法前运行,如果在通知中原始方法不运行

  • after

    • 在原始方法后运行,无论原始方法运行是否出现异常,都运行 相当于finally位置代码

  • after-returning

    • 在原始方法出现异常不执行,相当于直接在原始方法后加功能代码

  • after-throwing

    • 原始代码抛出异常执行,相当与catch内代码

  • around

    • 原始方法执行前后都可以执行,可以阻止原始方法执行,通知方法需要加一个参数为切点目标对象,调用切点目标对象proceed方法,则原始方法执行

通知顺序

  • 配置文件标签在前先执行

注解配置AOP

  • Aspect 定义在类上,设置当前类为切面类

  • Pointcut 定义在方法上,使用当前方法上定义的execution表达式

    • 可单独抽取一个类内写execution表达式进行注解
      使用时需要在引用时加上类名.方法名

  • 例: Before 定义在方法上,表示添加前置通知 value=”Pointcut定义的方法()”

  • 在spring配置文件中添加扫描通知注解标签

    也可在spring配置类中加注解EnableAspectJAutoProxy

AOP底层原理

静态代理

  • 装饰者设计模式:在不惊动原始设计的基础上，为其添加功能

    • 和要增强的实现类实现相同接口,对原有方法进行调用,再在下方进行要增强的操作

动态代理JDK Proxy

  • 创建一个类,使用JDK的Proxy.newProxyInstance方法,传入参数,强转成要增强的类型,再在参数三的匿名内部类中对原有方法进行增强

    • 参数一:原始对象的类加载器
    • 参数二:原始对象实现的所有接口
    • 参数三:创建一个invocationHandler对象,使用匿名内部类,用method调用invoke方法,对原有方法进行调用

  • 要求原始对象实现了接口,并对接口方法进行增强

动态代理 CGLIB

  • 不限定是否具有接口,也无需原始被代理对象

事务管理

概念

  • 使用aop进行方法增强,将多个事务进行统一管理,使一个操作达成成功则全部成功,失败则全部失败

事务特征(ACID)

  • 原子性（Atomicity）指事务是一个不可分割的整体，其中的操作要么全执行或全不执行
  • 一致性（Consistency）事务前后数据的完整性必须保持一致
  • 隔离性（Isolation）事务的隔离性是多个用户并发访问数据库时，数据库为每一个用户开启的事务，不能被其他事务的操作数据所干扰，多个并发事务之间要相互隔离
  • 持久性（Durability）持久性是指一个事务一旦被提交，它对数据库中数据的改变就是永久性的，接下来即使数据库发生故障也不应该对其有任何影响

编程式事务

  • xml

    • 创建事务管理器,注入数据源
    • 使用tx命名空间配置事务专属通知类
    • 使用aop:advisor在AOP配置中引用事务专属通知类

    • aop:advice与aop:advisor区别

      • aop:advice配置的通知类可以是普通java对象，不实现接口，也不使用继承关系
      • aop:advisor配置的通知类必须实现通知接口
        • MethodBeforeAdvice
        • AfterReturningAdvice
        • ThrowsAdvice

  • 使用AOP抽取

    • 编写AOP通知类

    • 注入dataSource

    • 使用环绕通知将通知类织入到原始业务对象执行过程中

声明式事务

  • 注解

    • @Transactional
      方法注解，类注解，接口注解,一般定义接口上

  • 纯注解

    • Spring注解配置类上@EnableTransactionManagement

事务的传播行为

  • PROPAGATION_REQUIRED:支持当前事务，如果没有事务会创建一个新的事务
  • PROPAGATION_SUPPORTS:支持当前事务，如果没有事务的话以非事务方式执行
  • PROPAGATION_MANDATORY:支持当前事务，如果没有事务抛出异常
  • PROPAGATION_REQUIRES_NEW:创建一个新的事务并挂起当前事务
  • PROPAGATION_NOT_SUPPORTED:以非事务方式执行，如果当前存在事务则将当前事务挂起
  • PROPAGATION_NEVER:以非事务方式进行，如果存在事务则抛出异常
  • PROPAGATION_NESTED:如果当前存在事务，则在嵌套事务内执行。如果当前没有事务，则进行与PROPAGATION_REQUIRED类似的操作

事务的隔离级别

  • 读未提交

    • 会出现脏读,不可重复读,幻读的情况

  • 读已提交（表级读锁）

    • 解决了脏读的情况

      脏读：一个事务读取到了另一个事务未提交的数据

  • 可重复读（行级写锁）

    • 解决了不可重复读的情况

      不可重复读：一个事务内读取到的数据不一致（主要指数据的更新）

  • 串行化（表级写锁）

    • 解决了所有的问题

      幻读：一个事务内读取到的数据刚才还存在，再次读取后又不存在（主要指数据的新增或删除）
